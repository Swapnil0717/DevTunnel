**Why?**

Two things go wrong, both from the same cause.

Spaces get deleted. `` `$BAR` from `c.sh` `` comes back as `` `$BAR`from`c.sh` ``, and the second
paragraph loses four more the same way. That's content loss rather than reformatting, and the result is
stable, so running Prettier again doesn't bring them back and nothing warns you about it.

Prose stops wrapping. The last two lines of the second paragraph get joined into one 181 character line
and left there, well past the 100 I asked for. 3.8.5 wraps the same text correctly.

The cause is inline math. Since 3.9.0 a `$ ... $` pair gets matched straight across backtick code spans,
so everything between the `$` in `**Uses $FOO**` and the `$` in `` `$BAR` `` becomes a single `inlineMath`
node. `--debug-print-ast` on the first paragraph:

3.8.5:

```
['inlineCode', 'paragraph', 'root', 'strong', 'text']
```

3.9.8:

```
['inlineCode', 'inlineMath', 'paragraph', 'root', 'text']
inlineMath value: 'FOO** from `a.sh` and `b.sh`, plus `'
```

That explains both symptoms. The math node swallows the closing `**` and both opening backticks, which
re-pairs every backtick after it, so ` from ` parses as a code span instead of plain text and CommonMark
strips one padding space from each side of it. And since math content is atomic it can't be broken, so
any paragraph containing one of these bogus nodes can no longer be wrapped.

CommonMark gives code spans precedence over other inline constructs, so a math span shouldn't be able to
start or end in the middle of one. I'm guessing this came along with the micromark upgrade in #18277,
since 3.8.5 parses the same line as `strong` + `inlineCode` and leaves it alone.

Not specific to lists or to `proseWrap`, I hit it first in a numbered list and a plain paragraph behaves
the same. Pretty easy to run into in any docs that mention shell variables more than once in the same
paragraph, `$HOME`, `$PATH`, `$DOTFILES` and so on. Thanks!
