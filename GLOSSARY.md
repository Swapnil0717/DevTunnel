# Glossary

Definitions of terms used throughout the DevTunnel codebase, docs, and issues.

---

**Bounty**
A paid task that any eligible contributor can claim and complete for a defined payout, rather than one assigned directly by the project owner.

**Contributor**
Any developer who joins a project on DevTunnel to complete tasks, submit pull requests, or otherwise participate in project work.

**Contributor License Agreement (CLA)**
The legal agreement contributors accept before their contributions can be merged. See [CLA.md](./CLA.md).

**Maintainer**
A user with elevated permissions on a specific project — able to manage tasks, review contributions, and organize the project's workspace.

**Paid Task**
A task funded by the project owner that a contributor is paid for upon approved completion.

**Private Project**
A project with restricted access, visible and available only to developers who meet the owner's defined requirements (skills, experience, prior activity, etc.).

**Project**
The central entity on DevTunnel — a software project with a description, tech stack, requirements, repository, tasks, contributors, and access rules.

**Project Health Score**
An informational score (e.g., 86/100) derived from repository signals — activity, issues, PRs, commits, stars, documentation — indicating whether a project appears active and well-maintained. Not an absolute judgment of quality.

**Project Owner**
The user who creates and controls a project on DevTunnel, defining its type, requirements, and access rules.

**Publish / Publication Workflow**
The state machine a project moves through before appearing publicly: `Draft → Review → Published`. Only `Published` projects are visible on the main website.

**Role Match Score**
A percentage score representing how well a contributor's current skills align with a specific project role's requirements (e.g., "Backend Developer — 87% match").

**Task**
A discrete unit of work within a project (e.g., "Fix authentication bug"), which may be free, paid, or a bounty, and is associated with a role, difficulty, and required skills.

**Validation Project**
A short, real-world project or task used by companies to evaluate a developer's actual skill and output, as an alternative or supplement to resumes and interviews.

**Validation Task**
An individual task within a Validation Project that a company reviews to assess a developer's real-world ability.
